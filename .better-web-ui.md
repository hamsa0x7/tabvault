# SmartTabber — Design & UX Context

## Design Context

### Users
Power users and knowledge workers managing dozens or hundreds of browser tabs across multiple windows and workspaces who value privacy, local-first reliability, and effortless session recovery.

### Brand Personality
- **Voice & Tone**: Clear, calm, trustworthy, utilitarian-craft. Plain language over enterprise or cryptographic jargon; makes users feel in control rather than punished or intimidated.
- **3-Word Personality**: Reliable, Transparent, Focused.
- **Emotional Goals**: Confidence that tabs and sessions are safe, clarity on what stays local vs. what syncs, and calm control over encryption and backups.

### Aesthetic Direction
- **Existing System**: Cool-slate bento surface system (`--st-canvas: #F5F7FA` / `#121419`, `--st-surface: #FFFFFF` / `#1A1D24`, `--st-accent: #0B87C9` / `#42A8E0`), subtle borders (`--st-border`), semantic warning/danger tokens (`--st-warn-*`, `--st-danger`), and `Barlow Condensed` + `Barlow Semi Condensed` typography.
- **Themes**: Light and dark mode (`html.dark`) with calibrated neutral ramps and high-contrast ink.
- **Anti-References**: Generic AI-slop gradients, neon glows, security theater (fake lock badges), jargon-heavy crypto copy, or alarmist/punishing error states.

### Implementation Defaults
- **Source**: Detected existing project stack (`package.json`, `src/styles/app.css`, `src/components/ui.tsx`).
- **Framework**: React 19 + TypeScript (strict) + Vite (Chrome Extension MV3).
- **Styling**: Tailwind CSS v4 (`@tailwindcss/vite`) with custom CSS variables in `src/styles/app.css`.
- **UI Primitives**: Radix UI (`@radix-ui/react-dialog`, `checkbox`, `dropdown-menu`, `switch`, `tabs`) + `lucide-react` icons + local `src/components/ui.tsx` wrappers.
- **Storage & Crypto**: IndexedDB (`idb`) + WebCrypto AES-GCM-256 (`src/shared/crypto.ts`).

### Design Principles
1. **Establish hierarchy with spacing and weight before adding color** — Keep security controls, warnings, and recovery guidance scannable in grayscale first.
2. **Earn trust through plain-language transparency** — Explain *what* encryption protects, *where* keys live, and *what happens* if a password is lost without cryptographic jargon or fear-mongering.
3. **Prevent irreversible mistakes before they happen** — Surface password strength, show/hide toggles, confirmation checks, and explicit "no password reset" recovery warnings *before* encrypting backups, not after data is locked.
4. **Preserve the cool-slate bento system** — Use existing `ui.tsx` primitives, `--st-*` / `--bento-*` tokens, and `lucide-react` icons consistently across Dashboard, Options, Popup, and Side Panel.
